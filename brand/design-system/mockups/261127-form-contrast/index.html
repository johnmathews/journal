Form contrast: borders, errors, focus

Formalising the design system measured today’s colours against its rules. Three form details fall short. Should each one be fixed, or kept as it is? Everything else stays as it is: layout, type, the greys, and violet with its two known misses.

Each fix is shown alone on the sign-in card, with the email field and the button drawn as if focused. The three are independent, so any mix works. The last section shows all three together.

Today

Option A for all three

Input borders in gray-200 (1.2:1). Error text in red-700, which reads at 3.6:1 in its pink box. A focused input darkens its border one step, and a focused button gets the browser’s own outline.

  • Input border on the card
  • Error text in its box

1. Input borders: B. Gray-500

Option 1B

Every input, select and checkbox border in gray-500 (#6b7280) in both themes, the system’s control-border. Fields read as fields at a glance. Dividers and card edges stay pale.

  • Input border on the card
  • Input border on the page

2. Error text: B. Red-800 in light

Option 2B

Error text in light mode moves one step darker, from red-700 to red-800 (#c52727, the system’s error-ink). Dark mode already passes and stays red-400. About 80 error messages change, all by this one step.

  • Error text in its box
  • Error text on the card

3. Focus: B. A solid ring in the accent

Option 3B

Anything reached with the keyboard gets a solid 2px ring in the accent colour, 2px off its edge, so it follows the user’s accent. A focused input’s border takes the accent too. Mouse clicks show no ring (:focus-visible), as today.

  • Ring on the card (violet)
  • Ring on the page (violet)
