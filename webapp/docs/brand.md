# Brand and design system

> Purpose
>
> This document says where Journal's brand lives, how its design system is kept, and how to change
> it. Read it before designing any screen.

## 1. The direction

Journal is quiet and personal: one person's notebook, read back to them. The screens are neutral
grey and white from the Cruip Mosaic shell, Inter throughout, and one accent colour that each user
picks (violet by default). The design system formalises that look as it is. It was not redesigned:
the brief (2026-11-27) was to align and formalise what is there, with no large visual changes.

## 2. The design system

The design system is a claude.ai artifact: https://claude.ai/artifact/B5VfW1xyBSaB71AQv8uBDL. It
holds the brand book, the tokens in light and dark, 14 components with live previews and
guidelines, the voice, and the app icon. Agents designing for Journal read its README first. The
artifact is private, so share it from its page before anyone else can open it.

Its source lives in this repository, at the same paths the artifact uses:

| Path | Contents |
| --- | --- |
| `brand/design-system/SYSTEM.md` | The artifact's URL |
| `brand/design-system/checks.json` | The gate's settings: required components, extra contrast pairs |
| `brand/design-system/project/design-system.json` | The index: title, asset records (upload ids) |
| `brand/design-system/project/tokens.json` | Every colour role, type style, space, radius and shadow |
| `brand/design-system/project/README.md`, `foundations.md`, `voice.md` | The brand book, the rules behind it and known gaps, and how Journal writes |
| `brand/design-system/project/components/<Name>/` | Each component's `README.md` and `preview.html` |
| `brand/design-system/project/assets/AppIcon/` | The app icon's masters (generated by `npm run icon:gen`) |
| `brand/design-system/mockups/` | One folder per visual decision |

## 3. How the app uses it

- **Colour.** `npm run tokens:gen` writes `src/assets/tokens.css` from `tokens.json`, and
  `main.css` maps each role to a Tailwind colour: `bg-canvas`, `bg-panel`, `text-ink`,
  `text-ink-secondary`, `border-line`, `border-control-border`, `text-error-ink`. Build new UI from
  these. The accent roles come from the user's scale in `accents.css`
  ([architecture.md](architecture.md#accent-colour-and-app-icon)).
- **Contrast and focus.** [architecture.md](architecture.md#colour-roles-typography-and-contrast)
  has the rules and the tests that hold them.
- **Charts** keep their own fixed data colours: [chart-style-guide.md](chart-style-guide.md).
- **Element names** for tests: [element-naming.md](element-naming.md).

## 4. Checks

- `scripts/check_design_system.py` is the gate. It checks token shapes, contrast in both themes
  (including the project's 7:1 aim for secondary text on panels), and a README and preview for
  every required component. CI runs it with `--complete` (`.github/workflows/design-system.yml`),
  and so does the pre-push hook when `brand/design-system/` changes.
- `npm run tokens:check` (webapp CI and pre-push) fails when `tokens.css` is stale.
- Webapp tests fail on a light-mode `text-red-N` error colour, a `border-gray-N` on a form control,
  or a missing role utility (`src/brand/__tests__/tokens.spec.ts`), and on any `violet-N` class
  (`brand.spec.ts`).
- `python3 scripts/design_preview.py brand/design-system` builds an offline gallery into the
  git-ignored `brand/design-system/preview/`.
- There is no browser (Playwright/axe) suite in the webapp, so the skill's `a11y.spec.ts` is not
  installed. Contrast is checked on the tokens and the previews instead.

## 5. Changing it

1. A visible change starts as a mockup (§6) and waits for the owner's pick.
2. Edit the files under `brand/design-system/project/`. If `tokens.json` changed, run
   `npm run tokens:gen` in `webapp/`.
3. Run the gate and the webapp tests.
4. After the change merges, publish only the changed files to the artifact with
   `root: brand/design-system`. Send `design-system.json` only when its own keys change, and last.
   Upload a new or changed SVG as an asset first, and record its id, size and type in the index.

Edits made on the artifact page itself are not in the repository: read the changed files back
before editing here.

## 6. Mockups

Each question gets a folder in `brand/design-system/mockups/<yymmdd>-<slug>/`: `index.html` (the
options, built from the tokens, both themes side by side) and `README.md` (the question, the
options, the decision and the link to the private artifact it was published as). The
design-system skill's `references/mockups.md` has the loop and its commands. `dist/` folders are
builds and are not committed.

## 7. Known gaps

`brand/design-system/project/foundations.md` lists every pairing that still misses the rules
(violet's button text and links by the owner's choice; warning text, the toasts, the danger
button, placeholders and remove icons still open), with measured ratios.
